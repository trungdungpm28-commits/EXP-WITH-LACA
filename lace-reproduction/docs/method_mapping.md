## Trace and workload reconstruction

- `data.py` checks the Microsoft archive digest, extracts only required day 1–4 CSVs, validates schemas and streams 512 rows at a time into compressed sparse per-day arrays. Keys comprise owner, application and function hashes. The parser keeps the first valid duplicate and records missing or invalid metadata, duplicate and accepted row counts. `data_validation.csv` records source files, digests and units-by-field schema. The cached source and sparse arrays can be reused.
- `workloads.py` reconstructs minute `m` (zero-based) with count `n` using offsets `60*i/n` seconds, for `i=0..n-1`, including whole-minute starts. Recordings remain aggregated trace data. A cross-function timestamp tie uses fixed function-index order. Outcomes are in milliseconds, timestamps and IAT in seconds, and footprints in decimal MB. The simulator divides the last available historical `AverageAllocatedMb` by the full historical population with at least two invocations in the application and rounds up to an integer MB. That calculation precedes experimental sampling and still counts functions with missing duration metadata.
- The chronological validation cut is 16:48 on day 3 (90% of the three calendar days). Day 1 calibrates static model inputs and supplies feature prehistory. Model examples begin on day 2 so day-1 metadata is already available. Candidate training functions are seeded and uniform among historical eligible day-1 functions up to 25,000 day-1 invocations. Sampled supervised positions retain complete earlier within-function arrival history. The two splits exclude final invocations with labels realized outside their split. Feature standardization and checkpoint selection use the training and validation splits respectively. Predictor IAT is learned on day 1–3 data only.
- Workload eligibility and strata use days 1–3. Representative uses a uniform draw from each of four historical frequency strata ranked by count, with hash order to break ties. Rare starts from the least active by historical count with the same tie-break. Random draws uniformly without replacement. Each held-out window is a contiguous prefix of day 4, ending at the last full-minute boundary that preserves the cap, with all functions and policies in that workload sharing it. Day-4 counts determine the cap boundary and report observed presence. They do not determine the cohort, scaler, model, or feature definitions. Unobserved cohort members remain in the manifest with zero invocations. Feature histories start on day 1 and the simulated cache starts empty.
- Common logical capacities are set before any measured comparison using the active footprint from the frozen input, the largest individual footprint, and proximity to paper points. This uses no policy outcomes or target IATs. Actual values and the resource budget are in `budgets.json`.
- The first campaign used the 30,000-request cap and kept the full historical frequency range. A handful of historically very active functions shortened Representative to four minutes, shorter than the TTL. The separate expanded campaign freezes a ceiling of 25,000 historical invocations per function for Representative and Random cohort draws and allows up to 100,000 held-out requests per workload. Rare and the memory-allocation population use the original eligibility rules. The expanded campaign studies a longer horizon and conditions its conclusions on this historical activity ceiling.

## Model and policy

| Paper reference | Path | Implementation and choices |
|---|---|---|
| §3.1, Eq. 2 | `workloads.py` | Eight gap lags encoded with log1p and -1 for unavailable lag. Ten EDCs have half-lives of 2^9 through 2^18 seconds and are observed at arrivals. Static inputs are log-scaled historical average duration, estimated initialization penalty and footprint, plus trigger indicators. Statistical inputs are cumulative count, 30-minute count and 30-minute share. The number of lags/counters and category encoding are local choices. |
| §3.1.2 and Fig. 6 | `workloads.py`, `model.py` | Realized next IAT is the regression label. No censored labels are synthesized. The figure orders four classes and gives no numeric cutoffs. Fixed operational cutoffs are 60, 600 and 3,600 s, with boundary cases in the higher class. |
| §3.2, Eqs. 3–11, §4.2 | `model.py` | Six 3-layer width-64 residual SiLU/LayerNorm MLP experts. Linear BatchNorm gate with learned positive noise scale during training, top-three softmax, and computation on selected rows only. Predictions combine shared weighted expert regression outputs and classification logits. Regression uses L1 on seconds divided by 600 and a positive softplus output. Auxiliary classification uses focal loss with gamma 2 and uniform class weighting. Eq. 11 optimizes log uncertainty. Eq. 10 has coefficient 0.1. Adam starts at 0.002 with plateau scheduling, gradient clipping at 5, batch target 512, and the lowest validation MAE checkpoint. Width, batch size, and epochs are reduced. Inference uses the fixed offline weights throughout. |
| §3.3, Algorithm 1 | `replay.py` | Refresh the resident priority at each access, admit a new container on a miss after freeing required capacity, and evict minimum priority first. Priority is `1/(1+predicted_IAT_s)`. Equal priorities use earliest update sequence. Replays use precomputed predictions from causal feature rows or equivalent single-request inference. |
| Eq. 1, §4.2, pinned FaasCache scheduler | `vendor/faascache/gdsf.py`, `replay.py` | Uses the upstream priority formula and cache-residency hit streak. A miss admits at frequency one, a hit increments it, and eviction clears resident frequency. The clock is updated to the last evicted key. This adapts the clone sum to one resident slot per function and evicts only for the capacity deficit. The paper describes decayed frequency. This run follows the released code’s in-cache streak. |
| §4.2 TTL and LRU | `replay.py` | TTL expires after strictly more than 600 seconds since last invocation, with LRU as its capacity-pressure rule. LRU has no expiration. |
| §4.2 HIST | Pre-run selection in `campaign.py` | LRU fallback. The pinned scheduler's HIST accounts for prewarm memory in its own container pool, but `PreWarmContainers` selects events with scheduled time greater than or equal to current time, clamps them to current time and can enqueue clones on consecutive arrivals. Its variance/mean test also differs from the paper’s CoV description. Faithful event-time integration would change that behavior. Zero prewarm events apply to all executed policies. |

All replays use a single atomically reusable container per function. Durations contribute to latency totals. They do not model execution overlap or multiple concurrent busy instances. The shared capacity rule evicts only enough space for a feasible admission. An oversized request would be serviced as an uncached cold invocation and flag the cell as non-comparable. Logs retain these counts, even when zero.

## Metrics and diagnostics

- The Azure trace has no measured initialization latency. FaasCache's trace generator uses `Maximum` as cold and `Average` as warm. Apply its **cost difference** to the most recent historical day available for each function. That same estimated penalty drives FaasCache priorities, LACE initialization features and policy overhead across the one base scenario. The day-4 average duration supplies each request's warm reference with historical fallback for missing day-4 rows. The day-4 average is only used to compute outcomes. This proxy can reflect runtime variation unrelated to cold initialization, so the absolute overhead can differ substantially from the paper.
- Figure 8 / Eq. 13. Compute `100 * (policy total ms - warm reference total ms) / warm reference total ms`. The simulator tracks the additive numerator directly. Figures leave gaps for zero warm reference or non-comparable cells.
- Figure 9 / Eq. 12. Compute `100 * cold invocations / all invocations`. A warm hit is a user invocation finding a resident container. The chart shows the empirical rate of the reduced replay.
- Figure 10 uses actual epoch history, loss in seconds and both learned sigmas. Figure 11 freezes the workload, split, seed, feature inputs and settings for the no-classification variant. Its regression-only loss retains regression uncertainty and the routing regularizer.
- Figure 12 uses top-three assignments, summed gate weights and mean weight across selected rows. Each series is normalized by its sum across six experts. Raw counts and weights are also exported.
- Figures 13–14 use fresh single replay workers. Linux `ru_maxrss` measures lifetime peak worker RSS in decimal MB. Policy CPU time is process CPU time from entry to policy work through cache decision, averaged across user requests. LACE invokes the model per request, including feature normalization. Feature history construction is done ahead of replay and is recorded in data-prep time. RSS includes the loading/runtime footprint, and LACE includes PyTorch and the feature matrix. These figures are host measurements.
- The Table 3-style evaluation uses exactly the same finite realized Representative IAT targets for both learned variants. Last invocations with no in-window successor are omitted from model scoring. MAPE also excludes zero targets. Cache metrics include these user invocations.
